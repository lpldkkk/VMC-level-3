# 内网渗透与高级社工-社交平台钓鱼-G1 WriteUp

打开靶机地址，看到一个社交平台的主页。页面上有三条动态，第一条来自带蓝V认证的「平台官方」账号 @official，内容提到"认准蓝V，谨防同形字仿冒账号"；第二条来自「安全中心」，同样强调"认准唯一官方 @official"；右侧栏"认证与安全"卡片也在警告"谨防同形字仿冒账号"。左侧导航栏有"主页"和"私信"两个可点击入口，当前身份显示为"访客 / 未登录"。

![01-home.png](https://k13in-images.oss-cn-wuhan-lr.aliyuncs.com/01-home.png)

点击左侧导航的"私信"链接，尝试直接访问 `/dm`，页面被 302 重定向到了 `/login` 登录页，说明私信功能需要登录后才能使用。登录页左侧同样展示了"认准蓝V认证""谨防同形字仿冒"的提示，这些反复出现的"同形字"关键词非常可疑，值得留意。

![登录页重定向](https://k13in-images.oss-cn-wuhan-lr.aliyuncs.com/02-login-redirect.png)

题目要求读取官方账号 @official 私信中的凭据，最直接的思路是注册一个名为 `official` 的账号。切换到注册页面，在用户名栏填入 `official`，密码填入 `pwn123`，点击注册按钮，页面返回红色错误提示"该用户名已被注册"。说明平台对用户名做了精确去重，`official` 这个名字已经被官方占用，无法直接注册。

![注册official失败](https://k13in-images.oss-cn-wuhan-lr.aliyuncs.com/03-register-official-fail.png)

回想页面上反复提到的"同形字仿冒"提示，联想到 Unicode 中存在全角拉丁字母（Fullwidth Latin Letters），它们在视觉上和普通半角字母几乎一样，但实际上是不同的码点。比如全角的 `ｏ`（U+FF4F）和半角的 `o`（U+006F）是两个不同的字符。如果平台注册时按原始字符串去重，那么全角版的 `ｏｆｆｉｃｉａｌ` 和半角的 `official` 是两个不同的用户名，可以通过去重检查。而如果登录或身份识别环节使用了 Unicode NFKC 归一化处理，全角字母会被归一化为半角字母，导致 `ｏｆｆｉｃｉａｌ` 被识别为 `official`，从而以官方账号身份访问私信。

在注册页面的用户名栏填入全角拉丁字母版本的 `ｏｆｆｉｃｉａｌ`（每个字母都使用 Unicode 全角形式：`U+FF4F U+FF46 U+FF46 U+FF49 U+FF43 U+FF49 U+FF41 U+FF4C`），密码填入 `pwn123`，点击注册按钮。

![填入全角用户名](https://k13in-images.oss-cn-wuhan-lr.aliyuncs.com/04-register-fullwidth.png)

注册请求发出后，服务器返回 302 重定向到 `/dm`，说明注册成功并自动登录。从 Burp Suite 的抓包可以看到，POST 请求体中 username 参数的 URL 编码形式为 `%EF%BD%8F%EF%BD%86...`（全角字符的 UTF-8 编码），响应的 `Location` 头指向 `/dm`，`Set-Cookie` 中 session 值已经包含了归一化后的身份信息。

![Burp抓包注册请求](https://k13in-images.oss-cn-wuhan-lr.aliyuncs.com/06-burp-register.png)

浏览器跟随重定向来到 `/dm` 私信页面。页面顶部显示 `@ｏｆｆｉｃｉａｌ · 官方账号`，左下角的登录状态也变成了 `@ｏｆｆｉｃｉａｌ / 已登录`。虽然显示的用户名是全角形式，但系统已经将当前身份归一化为 `official`，因此展示的是官方账号的私信收件箱。收件箱中有两条消息，第一条来自带蓝V认证的「平台安全中心」，正文为"【内部】本周官方认证账号的应急登录凭据备份：xxxxxxxx。请勿外泄。"，其中包含了 flag。

![私信页面获取flag](https://k13in-images.oss-cn-wuhan-lr.aliyuncs.com/05-dm-flag.png)

漏洞的根本原因在于平台的身份标识不一致：注册时使用原始字符串做去重（`official` ≠ `ｏｆｆｉｃｉａｌ`，可以通过检查），但登录和私信的身份解析使用了 `unicodedata.normalize("NFKC", name).casefold()` 对用户名做归一化（全角 `ｏｆｆｉｃｉａｌ` 归一化后等于半角 `official`）。这导致攻击者可以注册一个经 NFKC 归一化后与目标用户名碰撞的同形字用户名，用自己的密码登录后即以目标身份访问受保护资源。
